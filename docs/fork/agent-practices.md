# Практики разработки с ИИ-агентами

Источники проверены 2026-10-28. Это обоснование устройства репозитория,
а не обязательное чтение перед каждой задачей. Выбор модели не ограничен.

## Что применяем

| Практика | Решение в этом форке |
| --- | --- |
| Короткий постоянный контекст | [AGENTS.md](../../AGENTS.md) содержит цель, важные ограничения, команды и указатели. Подробности открываются по задаче. |
| Правила в нужной области | Локальные `AGENTS.md` добавляют только особенности своей директории; общие правила не копируются. |
| Одна версия каждого правила | [CLAUDE.md](../../CLAUDE.md) импортирует `AGENTS.md`; адаптер Copilot указывает на общие инструкции. |
| Документация по необходимости | В корне — условные маршруты «при изменении X прочитай Y», а не требование прочитать все документы. |
| Проверяемый результат | Задача задаёт результат и критерии приёмки; проверка использует существующие команды проекта и тесты затронутого поведения. |
| Небольшие независимые изменения | Сохраняем каталоги upstream; документация специфики форка находится в `docs/fork/`. Это упрощает сравнение и обновления. |
| Память без журнала переписки | Сохраняем решения, причины, незавершённую работу и результаты проверок. Вывод команд, повторные пересказы и историю диалога не переносим в стартовые инструкции. |

## Основания и границы применимости

**Codex.** Инструкции собираются по цепочке от корня проекта к рабочей
директории; более глубокий уровень уточняет общий. Стандартный предел
объединённых проектных инструкций — 32 KiB. Это предел инструмента, а не
цель наполнения. При работе из корня нужно явно находить инструкции для
затрагиваемых областей, не полагаясь на одинаковое поведение всех агентов.
Источник: [OpenAI — AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

**Минимум обязательного чтения.** OpenAI рекомендует пересматривать накопленные
инструкции, удалять повторы и направлять к документации по характеру задачи.
Требование открыть всю архитектуру перед небольшой правкой расходует контекст
без необходимости. Эти принципы применяем независимо от используемой модели.
Источник: [OpenAI — Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra).

**Общие и локальные правила.** Открытый формат разделяет пользовательский
`README.md` и инструкции агентам; вложенные `AGENTS.md` позволяют хранить
особенности рядом с кодом. Файл нужен там, где есть полезное локальное правило,
а не в каждой папке автоматически.
Источник: [AGENTS.md](https://agents.md/).

**Совместимость с Claude.** Используем `@AGENTS.md` в `CLAUDE.md`, сохраняя один
источник требований. Импорт поддерживает среды, где прямое чтение `AGENTS.md`
недоступно; на Windows он не требует настройки симлинков. Импорты загружаются
вместе с родительским файлом и сами по себе не экономят контекст. Поэтому
подробные руководства связываем обычными ссылками с условием чтения.
Источник: [Anthropic — project memory](https://code.claude.com/docs/en/memory).

**Совместимость с Copilot.** Поддержка `AGENTS.md` и приоритет инструкций
различаются между клиентами и функциями. Адаптер не должен содержать вторую
копию правил. Если конкретному клиенту нужны правила по маске пути, используем
его `.github/instructions/*.instructions.md` без противоречий общей политике.
Источник: [GitHub — custom instructions](https://docs.github.com/en/copilot/concepts/prompting-and-context/custom-instructions).

**Проверки вместо обещаний.** Агенту нужны команды с наблюдаемым результатом.
Инструкции модели не заменяют тесты, статические проверки и CI. Сложные задачи
получают краткий план с критериями завершения; простые правки не требуют
отдельного процесса планирования.
Источник: [Anthropic — best practices](https://code.claude.com/docs/en/best-practices).

## Наши ограничения размера и сопровождение

- Корневой `AGENTS.md`: не более 80 строк и 6 KiB UTF-8.
- Каждый локальный `AGENTS.md`: не более 45 строк и 4 KiB UTF-8.
- Это выбранные ограничения проекта, не требования производителей и не оценка токенов.
- Если файл растёт, сначала удаляем устаревшее и повторы, затем выносим детали
  в тематический документ с понятным условием чтения.
- После изменения структуры проверяем ссылки, команды и соответствие карте
  проекта. Устойчивые ограничения обновляем вместе с кодом, который их изменил.
- Сохранение структуры upstream и отдельный раздел форка — инженерный выбор
  этого проекта; указанные инструменты не требуют такой раскладки.
