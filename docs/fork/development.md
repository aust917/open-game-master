# Разработка и работа агентов

## Окружение

Версии — в [package.json](../../package.json), зависимости — в `package-lock.json`.
Для единообразия с upstream CI используем Node 24 и npm. Допустимый диапазон Node определяет `engines`.
В Windows команды `npm`/`npx` ниже можно выполнять как `npm.cmd`/`npx.cmd`.

Для изменения документации достаточно Node и Git; установка всего приложения не нужна.

```powershell
node scripts/check-agent-context.mjs
git diff --check
```

Для разработки приложения из корня:

```powershell
npm ci
npm run setup -- --no-build
npm run dev
```

`setup` создаёт `.env.server` с ключом базы, готовит content pack и скачивает модель памяти.
Это сетевые операции, возможны большой объём загрузки и сборка нативных зависимостей.
Существующий ключ базы сохраняй. Выбор модели и первый вход описаны в [install.md](../install.md).
В настройках кампании upstream уже есть `tableLanguage = russian`; это язык мастера, а не перевод всего UI.
Конкретный провайдер модели для форка пока не выбран.

Целевая схема — ПК с сервером и агентами, подключённый к нему телевизор и
смартфоны в общей Wi-Fi-сети; вход с телефонов через QR в браузер (R1 в [требованиях](requirements.md)).
Для доступа по LAN upstream предоставляет `npm run dev:lan` и `npm run start:lan`
(вторая команда требует сборки). Они слушают `0.0.0.0:3005`, но сами не настраивают HTTPS.
Голос с телефона проверяется через доверенный HTTPS и разрешение микрофона;
способ настройки описывается отдельной задачей. См. [voice-and-dice.md](../voice-and-dice.md).

## Проверки по изменению

| Изменение | Проверка |
| --- | --- |
| Только документация/инструкции | `node scripts/check-agent-context.mjs`, `git diff --check` |
| Проверяющий скрипт контекста | `node --check scripts/check-agent-context.mjs`, запуск и проверка отказа на повреждённой ссылке/превышении лимита |
| Логика или API | релевантные `scripts/test-*.mjs`, `npm run lint`, `npx tsc --noEmit` |
| UI | lint/typecheck и соответствующие сценарии [browser harness](../../scripts/browser/run.mjs), ручная проверка изменённого потока |
| Общая инфраструктура, обновление upstream, подготовка релиза | `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build` |

Поиск и точечный запуск:

```powershell
rg --files scripts -g 'test-*language*.mjs'
npm test -- scripts/test-language.mjs scripts/test-table-language.mjs
```

Набор запускается через [Vitest](../../vitest.config.mts); фильтр должен реально выбрать файлы.
Не заменяй покрытие поведения тестом, который лишь повторяет реализацию.
Прогон с заглушкой модели не доказывает качество живого рассказчика: проверку с реальным провайдером отмечай отдельно.
Не подключай пользовательскую базу к тестам; используй disposable fixtures существующего harness.

## Работа с контекстом

1. Прочитай корневые инструкции и применимые вложенные правила. Выбери одну область в [карте](architecture.md).
2. Ищи сначала по путям (`rg --files src/lib/dm`), затем по символам (`rg -n 'tableLanguage' src/lib/dm`).
3. Открывай ограниченные фрагменты. Большие SRD-таблицы, assets, lockfile, старые аудиты и планы нужны только при прямом отношении к задаче.
4. Сформулируй наблюдаемый результат, выполни изменение, проверь его и обнови соответствующий документ, если он устарел.
5. В передаче работы оставь изменённые пути, результаты проверок, открытый риск и следующий шаг. Не сохраняй весь диалог.

`AGENTS.md` содержит устойчивые правила, roadmap — текущую очередь, ADR — причину принятого решения.
Сложную задачу, продолжаемую между сессиями, оформляй в `docs/fork/tasks/<slug>.md` по шаблону ниже.
Папку и файл создавай только при появлении такой задачи; завершённые планы переноси в `tasks/archive/`.
Обычной небольшой правке отдельный план не нужен.

```markdown
# Название задачи
Статус: in-progress | blocked | done
Цель и критерии готовности:
Область: конкретные пути; ограничения совместимости
Шаги: короткий проверяемый список
Решения и факты: только то, что необходимо следующему агенту
Проверки: команда, результат; отдельно то, что не проверено
Следующий шаг / блокер:
```

Параллельным агентам назначай разные файлы или отдельные worktree; каждый получает цель,
критерии готовности и нужные пути. Интегрирующий агент проверяет общий diff; чужую работу не откатывает.

## Поддержка инструкций

Лимиты проекта: root `AGENTS.md` ≤ 80 строк / 6 KiB, вложенный ≤ 45 строк / 4 KiB;
адаптеры ≤ 15 строк / 1 KiB. Это наш бюджет текста, не оценка токенов и не лимит модели.
Проверка [check-agent-context.mjs](../../scripts/check-agent-context.mjs) контролирует размер,
локальные Markdown-ссылки и обязательные точки входа; доступность внешних сайтов не проверяет.
`CLAUDE.md` импортирует только общие инструкции. Copilot использует короткий адаптер;
поддержка вложенных правил зависит от клиента — при необходимости открывай их явно.
